# Addendum: PTS PRD

Supporting material for `prd.md`. It belongs downstream (architecture, UX) or is too detailed for the PRD itself. Requirements live in the PRD; if this file and the PRD disagree, the PRD wins.

## A1. Supplier File Template (draft)

- **File:** `pts-supplier-template.xlsx`, generated by `make_template.py`.
- **To regenerate:** `uv run --with openpyxl python make_template.py pts-supplier-template.xlsx`.
- **Contents:** five fictional example jobs for *Supplier Alpha (fictional)*, Export ID `EXP-20261108-0001`.

| Sheet | Purpose |
|---|---|
| `Instructions` | Supplier-facing instructions and rules. Protected. Shown first. |
| `Jobs` | One row per open job. Header row frozen. Columns A–J locked (grey), K–P editable (yellow). |
| `Lists` | Hidden. Allowed values for the three dropdowns. Protected. |

Build details implemented in the draft:

- **Dropdowns:** data validation of type *list* on K (status), L (on hold reason) and M (inspection type), referencing `Lists`. The error style is *stop*.
- **Completed quantity (N):** custom validation `AND(ISNUMBER(N2), N2=INT(N2), N2>=0, N2<=H2)`.
- **Expected completion date (O):** date validation later than 2000-01-01, formatted `yyyy-mm-dd`.
- **Conditional formatting (red)** for missing conditional fields:
  - L, when K = *On hold*
  - M, when K = *Ready for inspection*
  - P, when L = *Other*
- **New revision:** cells E and F filled light red, bold dark-red text, and F = `NEW REVISION`.
- **Header comments** explain the conditional rules.
- **Sheet protection without password.** Excel protection is easy to remove and is a guide only. PTS detects locked-column changes on import (W10).
- **Data rows only.** Empty rows are not unlocked, so suppliers cannot add jobs. A Job ID that is not in PTS is rejected anyway (R6).

Excel data validation only applies to typed input. Pasted values bypass it, and other spreadsheet programs may ignore it. This is why PTS validates every rule on import (PRD FR-9).

## A2. Technical Hints for Architecture

These are not decisions. `bmad-architecture` decides them.

- The lecturer suggested a standard Excel library, for example `openpyxl` in Python or an equivalent in JavaScript. The draft template uses `openpyxl` 3.1.
- Keep the architecture simple: one web app and one local database (lecturer feedback, criterion 5).
- FR-17 / NFR-1 suggest two storage areas:
  - **Staging:** imports and their rows, with validation results.
  - **Job data:** changed only inside the approval transaction.
- FR-20 means the change view should be computed from the stored file rows against current job data, not stored once at upload. For the import log (FR-21), the change view is frozen at decision time.
- **Exports must be stored with the values they contained.** Three rules depend on that:
  - W10 compares locked columns against the export, not against current job data.
  - W13 needs the list of jobs in the export.
  - W9 needs export order per supplier.
- A repository folder for example files and seed data (lecturer feedback, criterion 7), e.g. `testdata/`.

## A4. Rule ID Mapping

The brief numbers its rules 1–14 plus F1–F4. The PRD keeps those numbers and adds a letter for the kind of rule. R = rejection (rules 1–7) and W = warning (rules 8–14). For example, brief rule 8 is PRD W8.
